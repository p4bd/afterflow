# AfterFlow 评测：确定性引擎 vs 纯 LLM

> 固定 100 条跨域评测集（50 退款 / 25 逆向履约 / 25 运营预警），
> 同一份案件事实输入，对比「AfterFlow 决策引擎」与「纯 deepseek-v4-flash 直接回答」，
> 使用同一个模型无关评分器（`app/after_sales/evaluation.py`）。
> 可复现：`cd backend && PYTHONPATH=.:packages/harness uv run python scripts/evaluate_afterflow_baseline.py`

## 总体结果（2026-08-04 实测）

| 指标 | AfterFlow 决策引擎 | 纯 LLM (deepseek-v4-flash) |
| --- | --- | --- |
| 覆盖 coverage | 100.0% | 100.0% |
| 字段准确率 field_accuracy | **100.0%** | **60.3%** |
| **整案准确率 exact_case_accuracy** | **100.0% (100/100)** | **14.0% (14/100)** |
| └ refund（50 条） | 50/50 | 9/50 |
| └ reverse（25 条） | 25/25 | **0/25** |
| └ operations（25 条） | 25/25 | 5/25 |

## 字段级：LLM 到底错在哪

| 字段 | LLM 准确率 | 说明 |
| --- | --- | --- |
| `estimated_resolution_cost`（逆向成本） | **0%** | 成本经济学（退运+处理-残值）完全不会 |
| `severity`（预警等级） | 20% | 规则阈值判断差 |
| `alert`（是否预警） | 48% | |
| `refund_amount`（退款金额） | **52%** | 精确算术 + 封顶逻辑易错 |
| `risk_level`（风险等级） | 62% | |
| `action`（处置动作） | 64% | |
| `eligibility`（资格） | 74% | |
| `approval_required`（是否需审批） | 84% | 最简单的二元字段仍会错 |
| `outcome`（逆向结果类别） | 100% | 分类对，但金额/动作错 |

金额错误示例：`REF-002` 期望 1731 分、LLM 给 1831；`REF-003` 期望 2462、给 2662；`REF-004` 期望 3193、给 3493。

## 结论与意义

1. **决策引擎是确定性代码，不是模型能力**：100% 精确匹配衡量的是「代码正确性」（有单测），这是设计意图——把模型不可靠的部分从资金链路里移除。
2. **纯 LLM 对钱不可靠**：即使拿到完全相同的案件事实，LLM 的整案准确率只有 14%，金额精确率 52%，逆向成本 0%。
3. **这正是「为什么 LLM 不碰钱」的量化证据**：不是「觉得」LLM 算不准，而是有 100 条评测集证明它算不准。

## 方法说明（诚实口径）

- 纯 LLM baseline = 把每条案件的**结构化事实**直接给模型，让它输出与引擎相同的 JSON 契约；不给引擎规则、不给公式。这是「模型在该任务上的真实能力下限」的一种衡量——若换成只给用户口语描述，LLM 表现会更差。
- 引擎与 LLM 使用同一 `DecisionInput` 事实源、同一 `expect` 金标准、同一 `score_predictions` 评分器，无选择性抽样。

## 面试话术

> "我用 100 条跨域评测集（退款/逆向/运营）做了 baseline 对比：同一个案件事实，确定性决策引擎 100% 整案精确，纯 deepseek-v4-flash 只有 14%，退款金额精确率 52%，逆向履约成本 0%。**这说明不是'感觉' LLM 算不准钱，而是有量化证据**——所以我在架构上把金额、资格、成本全部下沉到确定性引擎，LLM 只做理解和沟通。"
